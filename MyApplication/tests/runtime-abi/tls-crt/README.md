# 真实 CRT、C++ TLS 与依赖终结夹具

这组 A/B 夹具供目标设备探针和真实 glibc 系统加载器对照共用。目标编译入口是上一层的
`build-tls-crt-fixtures.ps1`；所有对象、ELF、完整编译命令、输入摘要和收据由调用方指定到仓外目录。
夹具不定义 `__dso_handle`，不替代 `__cxa_finalize`，不关闭 C++ 异常或展开表。

目标编译显式使用当前 SDK 的 `crti.o`、`clang_rt.crtbegin.o`、`clang_rt.crtend.o`、`crtn.o`
以及 AMCL 锁定的共享 C++ provider。当前 SDK driver 默认生成 emutls；入口明确添加
`-fno-emulated-tls` 生成待验证的 AArch64 TLSDESC。`-nostdlib` 用于显式选定链接输入，
真实 CRT 并未省略。完整 driver 展开命令和最终 ELF 检查保存在该轮收据旁边。

## 公开接口

驱动只需持有 A 的公开 handle，A 通过真实 `DT_NEEDED` 依赖 B。
所有函数原型、事件常量均在 `fixture_api.h`；可以只复制原型到生产探针，避免把测试头作为产品依赖。

| A 的导出函数 | 输入与结果 |
| --- | --- |
| `amcl_sdk_tls_configure(sink)` | 配置事件接收函数。必须在其他夹具调用前执行；不触碰 TLS。 |
| `amcl_sdk_tls_resource_live()` | B 的静态资源已构造且尚未终结时返回 `1`。只在拥有 A handle 时主动查询。 |
| `amcl_sdk_tls_initial_value()` | 读取普通 TLS 指针，核实它与 B 全局对象同址后返回 `73`，地址不符返回 `-1`。不登记 C++ TLS 析构。 |
| `amcl_sdk_tls_touch(1)` / `(2)` | 首次触碰当前线程两个独立非平凡块级 TLS 对象；分别返回 `38` / `39`。无效编号返回 `-1`。 |
| `amcl_sdk_tls_enable_late(1)` | 使 A 的真实静态析构首次触碰 B 的 TLS 1；本函数本身不创建 TLS 对象。 |
| `amcl_sdk_tls_exception_roundtrip(token)` | B 抛出同一公开 C++ 类型、A 捕获；返回 token，事件依次为 `40/41(token)/42`。 |

`sink(int event, int detail)` 必须在夹具所有对象及工作线程生命周期内有效、线程安全且不抛异常。
夹具的 `configure` 和 `enable_late` 应在创建工作线程前完成，或在同一工作线程内执行。
通过线程创建、条件变量及 join 建立前后关系，不并发改这些配置。
关闭 A 后，驱动不得再调用保存的 A/B 函数指针；存活的析构回调由加载器和真实系统队列负责。

## 目标设备最小判据

每个场景使用新的夹具加载实例和独立工作线程。事件缓存位于已安装的宿主 DSO，
不能保存在被关闭的 A/B 中，也不能由事件总数猜测执行顺序。

1. **真实初值与 EH**：打开 A，配置接收函数，`resource_live()==1`、`initial_value()==73`；
   `exception_roundtrip(9041)==9041`，事件必须是 `40(0), 41(9041), 42(0)`。
   应在加载线程和后来创建的工作线程分别核验初值，覆盖模板与首次线程分配。
2. **已有 TLS 回调保活**：工作线程触碰 1 和 2 后暂停；另一持有者关闭 A；
   B 的静态资源不得提前终结。放行该线程正常返回并 join 后，TLS 析构事件必须按
   `21(2), 21(1)` 顺序完成，随后才允许 `30(0)`。A 的 `10/11` 各一次。
3. **fini 中首次触碰依赖 TLS**：不提前调用 `touch`，启用 late 并在工作线程关闭 A。
   关闭过程应出现 `10(0), 20(1), 11(0)`，此时 B 不得出现 `30`。
   工作线程返回后应出现 `21(1)`，然后 `30(0)`，且 A/B 的终结各执行一次。
4. **同一系统队列的交错**：在工作线程按 `touch(1)`、宿主真实非平凡 TLS 首次触碰、
   `touch(2)` 登记，退出应是 `21(2)`、宿主 TLS 析构事件、`21(1)`。
   宿主对象必须来自真实编译器/CRT，不能手工调用析构模拟通过。

所有场景均不得出现 `31`（B 的 TLS 析构观察到静态资源已经结束）。`31` 是稳定的失败证据；
夹具先检查独立存活标志，不对已经终结的 `Resource` 调方法。
`30` 与 `21` 的顺序证明静态资源生命周期，不单凭“库映射尚未解除”判断正确。

初值测试的 B 全局值和 TLS 指针均带必要的 `volatile`，阻止优化器把实际 TLS 读取、地址比较和
目标读取折叠为常量。构建脚本要求 `.tdata` 的真实 `R_AARCH64_RELATIVE` 指向该全局对象；
只有存在 `.tdata` 或函数返回常量，不足以证明覆盖了重定位后模板复制。

## glibc 参考实验

`run-glibc-reference.sh` 在固定 `amcl / qa` 中以宿主 g++ 和完整默认 CRT 编译同一 A/B 源码，
由 `glibc_reference.cpp` 使用真实系统 `dlopen/dlclose` 运行两个独立进程：

- `warm` 先构造 TLS，再关闭 A。此模式必须成功，核实夹具、跨 DSO EH、TLS 逆序析构和静态资源后置。
- `late` 在 A 的 fini 中首次构造 B 的 TLS。保存真实事件、退出状态与信号；不预设系统一定支持这个边界。

工作线程退出后若 glibc 延迟回收 B，参考程序只通过 `RTLD_NOLOAD` 获取仍已加载 B 的合法新 handle，
再关闭它触发系统的后续回收；不会重新构造 B，也不会在原 handle 关闭后调用裸函数指针。
每个模式均有有限的外部超时，只将超时记为未完成观察，绝不以等待时间到期证明 TLS 或线程已经终结。
`summary.json` 中“已收集”表示参考实验有结果，不能把 late 的原生信号分类写成正确性 PASS。
glibc 结论只适用于记录的宿主版本，不替代 OHOS SDK 产物的设备验收。
