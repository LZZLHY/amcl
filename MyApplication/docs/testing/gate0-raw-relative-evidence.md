## §1 这条能力到底断言什么（2026-08-23 改写）

改写前它断言的是「平台 `rawDelta` 字段是底层 raw HID 计数」。**那是一个来源命题，遥测
日志原理上无法证明** —— 日志只能看到值，看不到值是从哪条驱动路径来的。用一份写着
"是 raw HID" 的文档去批准一件数据说不了的事，比不批准更糟。

改写后断言三条**行为**性质：

| 编号 | 断言 | 为什么消费者需要它 |
|---|---|---|
| **R1** | **量纲可归一**：`rawDelta × density` 恒为整数像素 | POINTER_RELATIVE 才能有确定量纲。否则灵敏度换算是猜的 |
| **R2** | **与光标解耦**：`rawDelta` 不是由光标位移反算出来的 | 光标被 surface 夹紧/被 UI 吃掉时视角必须仍能转 |
| **R3** | **未加速**：指针加速作用在光标上，不作用在 `rawDelta` 上 | 视角灵敏度必须线性，否则快转与慢转的手感不一致 |

⚠️ 三条都**不**声称"这是 HID 报文"。它们声称的是"这个量可以当相对位移用"，而这正是
消费者真正需要的性质。来源问题因此从阻塞项降级为无关项。

| **光标完全不动（`Δpx == 0`）而 `rawDx != 0`** | 200/645 | 435/713 | **R2**（最强的一条） |
| 左边缘夹紧（`localX == 0`）时 `rawDx != 0` | 93/94 | 41/48 | **R2** |
| 剔除 `Δpx == 0` 后 \|`Δpx / (rawDx × density)`\| 中位 | 2.375 | 2.286 | **R3** |
| 同上，按幅度分桶中位（≤2px / 2-5 / 5-20 / >20） | 2.000 / 2.000 / 2.667 / **4.360** | 1.500 / 2.000 / 2.625 / **4.846** | **R3**（单调升 ⇒ 加速在光标那一侧） |
| `native.ts` 单调性违例 | 0 | 0 | 与 bit14 相关，非本条 |

**R3 的读法**：如果 `rawDelta` 也被加速，比值应当与幅度无关（两边同时被同一个函数放大）。
比值随幅度**单调不减**（A 日志 2.000→4.360，B 日志 1.500→4.846 —— 成立的是单调性，两份的
起止值不同，引用时不要把某一份的四个数说成两份共有），只能是**一侧被加速而另一侧没有**；
而被加速的必然是光标（加速是给光标做的）。⇒ `rawDelta` 是线性的。

## §4 未闭合的缺口（G1–G7）

**七条全部闭合才可批准。** 每条都写清了"要什么数据"，而不是"要跑什么测试"。

| 编号 | 缺口 | 要什么 |
|---|---|---|
| **G1** | 未证明 `density` 就是 `displayPixels`。R1 的归一化用的是 ArkTS 下发的 density，没有与显示屏物理像素对账 | 一台已知物理分辨率的设备上，`surface 宽 == 逻辑宽 × density` |
| **G2** | 设备矩阵只有一台 MatePad、`deviceId` 只有 `11`、density 只有 `2.125` 一档 | ≥2 台设备、≥2 档 density（1x/2x/3x 任二） |
| **G3** | 只测到 surface **边缘夹紧**，没测 surface **外** | 光标锁定后把鼠标推到 surface 外仍持续报 `rawDelta` |
| **G4** | 没测**丢失捕获**后的连续性（切后台 / 失焦 / 锁屏 / 息屏返回） | 一次捕获丢失前后的 `rawDelta` 序列，看有无跳变或静默 |
| **G5** | 未确认是否存在**不上报** `rawDelta` 的设备/输入路径 | 至少一台异型设备（蓝牙鼠标 / 触摸板 / 远程桌面注入）的样本 |
| **G6** | **光标锁状态在日志里不可观测** ⇒ 无法排除部分样本处于非锁定态 | 遥测行里补一个锁状态字段（需改探针） |
| **G7** | **采样完整性未证**：无丢样计数 ⇒ 无法排除遥测自身丢样，使"相邻对"实际不相邻 | 遥测行里补 `seq` 连续性统计（`seq` 已有，只是没统计跳号） |

⚠️ **G6 与 G7 是本卷宗自身的方法论缺口**，不是设备缺口：§3 里 R2/R3 的两条统计都建立在
"相邻样本真的相邻"和"这些样本都处于锁定态"之上。它们不闭合，R2/R3 的级别封顶在 **B 级**。
