# 唯一 look owner 与实际运输的宿主验证

`scripts/test-look-execution.py` 编译生产 `look_execution.cpp`、Core、control owner、旧 source 薄适配与实际 bridge。GLFW prefix callback 函数体从产品源码提取，fixture 只替换窗口结构、平台产品/schema admission 和可编程 typed transport；没有复制数学、速度积分、prefix 或 owner 算法。

运行必须显式指定仓外日志及构建目录，例如：

```powershell
python scripts/test-look-execution.py --out D:/dhao1/desktop/AMCL/.workspace/run/input-core/look-run --build-out D:/dhao1/desktop/AMCL/.workspace/build/look-run
```

同脚本 `--negative cache` 只撤实际 GLFW cache 写入，`--negative pressure` 只撤 bridge 真实容量拒绝。两种负控必须编译成功并以 `LOOK TRANSPORT FAIL` 行为断言失败；编译失败、超时或平台异常不能冒充有效反控。

覆盖范围包括旧 source 参数/数学回归、两手柄同 family 一次公共系数、精确轴 t0/动作 t10/tick t16 的 10.8+6.48 前缀、已准备票遇源退休后的撤销/兄弟重试、Mouse 独立关闭与重建、超过 512 次流开关而 handle 不复用、Native mapped compat 设备 0、实际 delta producer、四个 gyro 私有租约函数、同政策幂等及旧政策/资源拒绝、原 token 重复退休与陌生 token 拒绝。

`look_physical_core_test.cpp` 使用真正 Core、GLFW adapter 和 `backend_input_bridge.cpp` 的三消费者轨迹，显式制造 Core sequence 与 interactionOrder 数值不同，核两个私有索引关联同一 token；核原 raw 字段不改、同事实统计只增加一次、Core float 失败 batch 的 queue/sequence/统计与 look 数学/memo 全部回滚、设备移除接受点撤未应用贡献、同 id 重加获新 stream，以及 inactive surface 不授权新 look。host fixture 的 Gate0 能力声明只支撑源码测试，不能作为真实设备能力证据。

失败 batch 可烧掉未发布的共同 order 并留下 gap。公共 fence 是已分配编号的上限，不是“全部这些编号都对应成功输入”；Core/ring reader 只读取实际发布记录且不等待缺失号，因此不能回退全局单调计数来复用旧身份。失败 batch 不得留下可消费半批或假 prefix。

两个实际 owner DLL 的身份测试核同映像导出/可执行地址/PID/唯一 Core，损坏 ENV、错误导出及第二 Core 均拒绝，借用 DSO 保留至进程结束。`test-control-owner-teardown.py` 对真实 global facade/adapter 的正常退出观察 registry 与 Host Core 的实际析构时机：生产进程 pin 对象覆盖借用者，generic 局部 Core 仍 RAII；仅撤回原 storage 的可编译负控确定失败。正例正常 `return`，没有 `_Exit` 绕过析构。

这些证据证明 Native 接受/加工的因果顺序、该 ABI cache 可用前缀、真实 GLFW callback 顺序及实际 backend 运输。SDL SDK 的真正 ADD/Poll 与 LWJGL2 JNI/Java poll/next 由对应专门集成测试证明。它们均不能证明 Minecraft 已在独立 game tick 中使用该方向执行攻击/放置；最终 OHOS SDK 资产、四产品 HAP/APP 与设备验证还需绑定最终产物另行审核。

## SDL共同来源实际消费复用门

`scripts/test-sdl-source-delivery.py` 为Windows/MSVC明确维护一个需要完整已编SDL static SDK的集成入口；其它平台调用会失败，不登记成默认Ubuntu全量preflight成功。复用树由参数指定，产物与日志显式在仓外：

```powershell
python scripts/test-sdl-source-delivery.py --sdk-host-tree D:/dhao1/desktop/AMCL/.workspace/run/input-core/p5-sdl-host-final1 --out D:/dhao1/desktop/AMCL/.workspace/run/input-core/sdl-source-run --build-out D:/dhao1/desktop/AMCL/.workspace/build/sdl-source-run
```

该入口链接实际Source、Core、backend、bridge及JNI正文、完整SDL static SDK，抽取维护SDK的真实OHOS消费与键/鼠标映射。A–F、左/右/中键同时核事件和Poll缓存；compat/touch/gamepad/typed physical共持、六码加look前缀、whole预算拒绝及无新输入时Deferred末松分别断言。窗口发现、capture、text及菜单光标仍是明确夹具边缘，本门不覆盖这些平台功能。

`--negative compat-bypass` 撤真实JNI共同归约，`--negative budget2` 撤全批运输预算，`--negative simplified-mapping` 在外置consumer恢复错误的枚举强转/加一映射。三者必须实际编译并命中CHECK，正常进程、超时或编译失败不能算负控通过。每模式独立小目标，日志独占新目录，复用构建需显式 `--reuse-build`。

提取前封存helper、固定fixture、实际工程与SDK源/头/生成头、库及配方，结束再核相同字节，另绑定生成consumer/support/CMake与执行二进制。源码当前hash与库before/after稳定分别报告；不能因此补造旧static SDK建库收据。既有SDK镜像头注释与后来工程头有差异时，必须明确其实际身份，不以ABI相同声称新头已重新建库。最终仍需要同源OHOS库及四产品审核。
