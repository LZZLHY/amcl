# 兼容性与故障反馈

想知道某个整合包能不能玩，先记下 **设备与系统、Minecraft 版本、Java 版本、加载器和模组**。如果问题出在画面，再加上图形后端。这些信息能帮助你找到相近的实测记录，也能让另一位玩家或维护者重现问题。[第一次进入游戏](../README.md#第一次进入游戏)

## 为游戏选一套能用的配置

| 要选什么 | 怎么选 |
| --- | --- |
| 应用与设备 | 通用侧载包面向鸿蒙手机、平板和电脑（2in1），声明的最低兼容版本为 HarmonyOS 6.0.0（API 20）。如果下载页另有电脑专用包，该产品仅面向 2in1，最低为 6.0.2（API 22），使用桌面操控界面。[官网下载](https://amcl.lovedhy.cn/download) · [产品配置](../MyApplication/config/products.json) |
| Java 运行时 | 在 AMCL 中保留 Java 自动匹配。启动器会结合游戏清单和加载器限制选择 JDK，缺少时可按提示下载。手动为某个实例固定过 Java、换版本后又启动失败时，先检查该实例的 Java 设置。鸿蒙运行包有 8、17、21、25 四个主版本，各自按需安装。[运行时说明](https://amcl.lovedhy.cn/docs/jdk) |
| 加载器与模组 | 按模组文件注明的 Minecraft 版本、加载器和前置依赖安装。版本页支持直接安装 Fabric、Forge 和 NeoForge。排查已有整合包时，记下整合包版本和自己增删过的模组。 |
| 图形与操控 | 首次运行可保留「设置 → 显示与操控 → 图形后端」里的「自动选择」。手动选过后端时，记下选项名称。反馈触控或鼠标问题时，说明用的是触屏、实体键鼠还是手柄，以及问题发生在菜单还是世界里。 |

### 哪些组合实际进过世界？

下面两组记录来自同一台 MRDI-W10 平板（API 26），使用 AMCL `1.0.7-pre1` 开发测试包、指定的鸿蒙 JDK 和离线账号。两组都完成了新建世界、保存、退出，再重新启动游戏读回同一存档。换设备、换模组版本或换成公开侧载包后，需要在相应环境下验证。[平板游戏验证记录](https://github.com/LZZLHY/mc-ohos-resources/blob/main/docs/tablet-jdk-games-2026-11-11.md)

| Minecraft | Java 与加载器 | 实测模组 |
| --- | --- | --- |
| 1.12.2 | JDK 8 · Forge 14.23.5.2864 | JEI 4.24.0.1042 |
| 26.1.1 | JDK 25 · Fabric Loader 0.19.3 | Sodium 0.8.9 + Fabric API 0.145.4+26.1.1 |

第二组最初使用的 Fabric API 版本与 Sodium 冲突。保持设备和 JDK 不变，改用表中的 Fabric API 后才成功进入世界。如果你也遇到加载器报错，把它点名的模组、依赖和版本一起记下，通常比只贴退出码更容易定位。

## 按故障发生的位置排查

| 你看到的现象 | 先做什么 | 反馈时附什么 |
| --- | --- | --- |
| HAP 下载好了，但安装失败 | 确认下载的是适合设备的 HAP。文件名含 `unsigned` 时，按侧载图文完成用户签名和安装。[侧载安装图文](https://amcl.lovedhy.cn/docs/install-hokit) | HAP 文件名、设备与系统、安装工具给出的错误原文。 |
| 游戏、模组或运行时下载失败 | 到「活动账本」打开失败的下载，确认停在哪个文件或阶段。 | 资源名、目标版本、失败时间和对应下载记录。 |
| 点启动后停在「启动前检查」 | 看哪一项未通过。提示缺少 JDK 时下载推荐版本。提示即时编译（JIT）不可用时，记下系统版本和检查结果。 | 未通过项目的原文或截图，以及选用的 Java。 |
| 原版能进，加模组后退出 | 用独立游戏目录建一个同版本的测试实例和新世界，先试所需加载器，再逐组加入模组及前置依赖。 | 最小可复现的模组组合、各自版本和失败那次活动的日志。 |
| 黑屏、花屏、鼠标或触控异常 | 记下是在标题菜单、加载世界还是进入世界后发生。若手动调过图形设置，可恢复「自动选择」再比较一次。 | 设备型号、图形后端、输入方式、复现步骤，以及能看出差异的截图或日志。 |

## 找到这一次失败的日志

1. **刚看到「游戏异常退出」时**，点「分析日志」进入本次的「活动详情」，再点「查看相关日志」。
2. **已经关掉弹窗或重试过时**，打开「设置 → 活动账本」，按时间和游戏版本找到失败的那一条。点右侧「⋯」，选「查看活动详情」或「查看原始日志」。重试会产生新活动，反馈时用出问题的那次。
3. **只需几行错误时**，在相关日志中找到那条事件，点「操作 → 复制事件（脱敏）」，把错误和紧邻的上下文贴到反馈中。
4. **需要分享多个文件时**，回到该条活动的「⋯ → 自定义分享与预览」，勾选相关文件，点「预览并继续」。检查令牌、账号信息、服务器地址和个人路径，确认可以公开后点「确认公开分享 → 复制链接」。持有链接的人都能查看分享内容。

## 提交反馈

相同问题可先在 GitHub Issues 搜索，有同样的复现条件就补充到原单。新问题可以使用 GitHub 的「问题与构建失败」表单，也可以通过官网反馈页提交。走官网时，把日志链接放在问题描述里，截图用附件上传。[GitHub Issues](https://github.com/LZZLHY/amcl/issues) · [新建 GitHub 问题](https://github.com/LZZLHY/amcl/issues/new/choose) · [官网反馈](https://amcl.lovedhy.cn/feedback)

下面几行可以直接复制。没能进到游戏的情况，写出最后走到哪一步就够了。

```text
AMCL 版本和产品（如通用侧载稳定版）：
设备型号和系统版本：
Minecraft、JDK、加载器及相关模组版本：
图形后端或输入方式（画面、操控问题填写）：
复现步骤：
预期结果与实际结果（含错误原文）：
失败时间、脱敏日志片段或分享链接：
```

如果失败发生在**从源码构建 AMCL** 的过程中，请提供公开仓提交号、主机系统、SDK 和工具版本、失败的命令及第一条相关错误。[公开构建说明与常见错误](../MyApplication/docs/BUILD_SNAPSHOT.md)
